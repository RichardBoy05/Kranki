## 14. Consegna

### 14.1 Modalità di rilascio
Le procedure di rilascio e consegna del progetto al committente seguiranno rigorosamente le linee guida definite per la valutazione accademica. La consegna non prevederà l'invio di archivi compressi fisici, ma coinciderà in modo trasparente con lo stato finale della repository GitHub al termine della fase di *code freeze* (fissata inderogabilmente a 5 giorni prima della data di presentazione). 

### 14.2 Artefatti di consegna (Deliverables)
Il pacchetto di rilascio ufficiale si comporrà dei seguenti elementi:
* **Codice sorgente**: l'intera *codebase* del sistema funzionante, opportunamente versionata. La repository includerà i file di configurazione degli ambienti di sviluppo (es. i file `.project` per l'importazione) e farà un uso corretto del file `.gitignore` per escludere i file autogenerati non necessari.
* **Documentazione**: un unico file in formato PDF, organizzato in capitoli, contenente la specifica dei requisiti, la documentazione architetturale e di design, e i report delle attività di testing e manutenzione.
* **Presentazione e live demo**: slide di supporto all'esposizione orale (redatte utilizzando l'apposito *template* fornito dalla committenza). Il team predisporrà inoltre un terminale (PC) preventivamente configurato per l'esecuzione di una dimostrazione pratica interattiva (*live demo*) del software funzionante durante la sessione d'esame.
